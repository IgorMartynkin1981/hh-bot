# hh_bot — браузерная автоматизация hh.ru на Rust

Автоматизированный помощник для поиска работы на [hh.ru](https://hh.ru): логинится
в аккаунт в реальном браузере, обновляет резюме, ищет вакансии под резюме,
ранжирует их по релевантности и откликается на лучшие — с полной имитацией
человеческого поведения, чтобы сайт не определял бота.

> **Важно (дисклеймер).** Автоматизация hh.ru противоречит правилам сервиса и
> несёт риск блокировки аккаунта. Проект создан в образовательных целях.
> Используйте ответственно: умеренная частота, лимит откликов, человеческие задержки.

---

## 1. Что делает приложение

Полный цикл «нашёл → откликнулся» без ручной рутины:

1. **Вход в аккаунт.** Бот поднимает настоящее окно Chrome с постоянным
   профилем, подставляет логин/пароль в формы hh.ru «по-человечески» (по буквам,
   с паузами), нажимает кнопку входа. Если сервис запросил капчу или проверку —
   вы решаете её вручную прямо в этом же открытом окне. После успеха cookie
   сессии сохраняются в файл и при следующих запусках вход выполняется мгновенно.
2. **Резюме.** Резюме можно описать в структурированном JSON или обычном
   Markdown-файле; бот заполняет поля формы резюме на hh.ru так же «по-человечески».
3. **Скрининг вакансий.** Бот выполняет поиск на hh.ru по ключевым словам
   резюме, собирает с первой страницы выдачи карточки (заголовок, компания,
   зарплата, регион, сниппет обязанностей, ссылка) и считает каждой вакансии
   **score релевантности**.
4. **Отклики.** Из отранжированного списка берутся только вакансии с ненулевым
   score, не больше лимита `max_applies_per_run`, и на каждую отправляется
   отклик: открытие вакансии → клик «Откликнуться» → при появлении модалки —
   подтверждение отправки (с человеческими паузами между действиями).

Всё доступно двумя способами: через **веб-интерфейс** (`serve`) и через **CLI**.

## 2. Подготовка и запуск

### Требования

- Google Chrome (или Chromium) — устанавливать ничего не нужно, используется системный Chrome
- `chromedriver` (версия должна совпадать с версией Chrome), запущенный отдельно
- Rust toolchain (MSRV 1.85)

### Установка

```bash
cd hh-bot
cargo build --release
```

### Запуск chromedriver (в отдельном терминале)

```bash
chromedriver --port=9515
```

### Конфигурация

Файлы лежат в каталоге конфигурации:

| Платформа | Путь |
|-----------|------|
| macOS | `~/Library/Application Support/hh_bot/` |
| Linux | `~/.config/hh_bot/` |

| Файл | Назначение |
|------|------------|
| `credentials.json` | Логин и пароль от hh.ru: `{"login": "...", "password": "..."}` |
| `config.json` | Настройки бота (см. ниже) |
| `resume.json` | Структурированные данные резюме |
| `resume.md` | (опционально) резюме в Markdown, разбирается командой `resume-md` |
| `session.json` | Сохранённые cookie сессии (создаётся после первого входа) |
| `chrome-profile/` | Постоянный профиль Chrome (создаётся автоматически) |

`config.json`:

```json
{
  "headless": false,
  "slow_mo_ms": 400,
  "storage_dir": "/путь/до/config/hh_bot",
  "profile_dir": "/путь/до/config/hh_bot/chrome_profile",
  "max_applies_per_run": 10
}
```

| Поле | Описание |
|------|----------|
| `headless` | `true` — Chrome без окна (для серверов); `false` — видимое окно |
| `slow_mo_ms` | базовый «замедлитель» — служит для глобального замедления действий |
| `storage_dir` | где хранятся `session.json` и прочие данные сессии |
| `profile_dir` | каталог постоянного профиля Chrome (реальные cookie, история, логины) |
| `max_applies_per_run` | максимальное число откликов за один запуск `apply` |

Если `config.json` отсутствует, применяются значения по умолчанию.

### Два способа запуска

**Веб-интерфейс (рекомендуется):**

```bash
cargo run --release -- serve
# → http://127.0.0.1:8787
```

**CLI:**

```bash
cargo run --release -- login       # вход и сохранение сессии
cargo run --release -- scan        # скрининг и рейтинг вакансий (JSON в stdout)
cargo run --release -- apply       # скрининг + автоматические отклики
cargo run --release -- resume      # обновить резюме на hh.ru из resume.json
cargo run --release -- resume-md   # разобрать resume.md → resume.json
cargo run --release -- upload [файл]  # файл → парсинг → загрузка на hh.ru
cargo run --release -- test-login  # quick-check, что вход работает
```

## 3. Команды CLI

| Команда | Что делает |
|---------|------------|
| `serve` | Запускает веб-сервер с панелью управления на `127.0.0.1:8787` |
| `login` | Открывает браузер, выполняет вход (seauty: возобновляет сессию из cookie или полный логин), сохраняет cookie |
| `test-login` | Поднимает сессию (тот же механизм входа, что и `login`) и выходит |
| `resume` | Открывает форму резюме на hh.ru и вносит в неё `title` и `about` из `resume.json`; печатает превью текста |
| `resume-md` | Читает `resume.md`, разбирает его в `resume.json` для дальнейшего использования |
| `scan` | Ищет вакансии по ключевым словам, ранжирует и печатает JSON-список (см. структуру `Vacancy`) |
| `apply` | Как `scan`, но дополнительно кликает отклики на релевантные вакансии (до `max_applies_per_run`) и печатает результат по каждой |

Пример вывода `scan` (JSON, поле `score` — рейтинг релевантности от 0 вверх):

```json
[
  {
    "id": "1073627473",
    "title": "Rust разработчик",
    "company": "Пример ООО",
    "salary": "от 300 000 ₽",
    "area": "Москва, удалённо",
    "link": "https://hh.ru/vacancy/1073627473",
    "snippet": "Разработка сервисов на Rust и Tokio...",
    "score": 6
  }
]
```

## 4. Веб-интерфейс (`serve`)

Одностраничная панель управления (axum + встроенный HTML/JS, тёмная тема) на
`http://127.0.0.1:8787`. Не требует внешних статических файлов — всё внутри бинарника.

### Возможности панели

1. **Войти на hh.ru** — кнопка в шапке: выполняет вход ботом; при капче вы
   проходите её в открытом окне Chrome.
2. **Редактор резюме** — форма с полями:
   - желаемая должность;
   - ожидаемая зарплата;
   - регион;
   - «о себе» (textarea);
   - навыки (списком через запятую);
   - ключевые слова для поиска (через запятую);
   - опыт в годах.
   - **Сохранить резюме** — пишет данные и на диск (`resume.json`).
3. **Скрининг вакансий** — запускает поиск по текущему резюме, отображает
   карточки (заголовок, компания, регион, зарплата, ссылка «открыть», badge рейтинга).
4. **Откликнуться** — скрининг + автоматические отклики; по каждой вакансии —
   зелёный badge `applied` или красный `failed`.
5. **Импорт резюме из Markdown** — два варианта:
   - выбор `.md`-файла через `input[type=file]`;
   - вставка текста markdown прямо в textarea.
   После «Разобрать и загрузить» данные парсятся, обновляют форму и сохраняются
   в `resume.json`.
6. **Журнал** — лента действий/ошибок в реальном времени (сниппет лога операций).

### API (JSON)

| Метод | Путь | Действие |
|-------|------|----------|
| GET | `/` | HTML-панель |
| GET | `/api/config` | Текущий `Config` |
| GET | `/api/resume` | Текущее резюме |
| POST | `/api/resume` | Сохранить резюме (`ResumeData` в теле) |
| POST | `/api/resume/md` | Разобрать markdown (`{"markdown": "..."}`) и сохранить |
| GET | `/api/login` | Вход на hh.ru |
| GET | `/api/scan` | Скрининг вакансий |
| GET | `/api/apply` | Скрининг + отклики |

Ответы единообразны: `{"ok": true|false, "data": ..., "error": "..."}`.

## 5. Форматы резюме

### `resume.json` (структурированно)

```json
{
  "title": "Rust-разработчик",
  "desired_salary": "250000 руб",
  "about": "5 лет в системном программировании, больше 3 лет с Rust...",
  "skills": ["Rust", "Tokio", "Async", "HTTP", "CLI"],
  "keywords": ["Rust", "Tokio", "системный разработчик"],
  "experience_years": 5,
  "area": "Москва"
}
```

> `keywords` обязательны: по ним формируется поисковый запрос
> (`search_query = keywords.join(" ")`). Без ключевых слов запуск блокируется.

### `resume.md` (Markdown)

Парсер понимает RU/EN заголовки секций и два способа их применить: сплошным
текстом или списком. Поддерживаемые секции:

| Секция (синонимы) | Во что попадает | Пример |
|-------------------|------------------|--------|
| `# Должность` | `title` (обязательно) | `# Rust-разработчик` |
| `## О себе`, `about`, `описание`, `summary`, `profile`, `резюме-текст` | `about` | многострочный текст |
| `## Зарплата`, `salary`, `желаемая зарплата`, `ожидаемая зарплата`, `зп` | `desired_salary` | `250000 руб` |
| `## Регион`, `area`, `город`, `location`, `city` | `area` | `Москва` |
| `## Навыки`, `skills`, `компетенции`, `stack`, `технологии` | `skills[]` | список `- Rust` или `Rust, Tokio` |
| `## Ключевые слова`, `keywords`, `поиск`, `search` | `keywords[]` | `Rust, Tokio` |
| `## Опыт работы`, `experience`, `стаж`, `years`, `лет работы` | `experience_years` (берутся цифры) | `5 лет` |

Пример:

```markdown
# Rust-разработчик

## О себе
Делаю высоконагруженные сервисы.
Увлекаюсь системами.

## Желаемая зарплата
250000 руб

## Регион
Москва

## Навыки
- Rust
- Tokio
- HTTP

## Ключевые слова
Rust, Tokio, бекенд

## Опыт работы
5 лет
```

Если секция — список (несколько строк или строки со `-`), элементы разбиваются
по строкам; если секция — строка, список разделяется запятыми.

## 6. Как всё устроено внутри

### Модули

```
src/
  main.rs     — точка входа: разбор CLI-команд, загрузка конфигов, запуск serve
  web.rs      — HTTP-сервер axum (панель + JSON API) и встроенный HTML-интерфейс
  app.rs      — переиспользуемые сценарии: open_session / login / update_resume /
               scan / apply (единый конвейер)
  session.rs  — запуск Chrome с постоянным профилем, вход, восстановление и
               сохранение cookie сессии (session.json), ожидание ручного логина
  stealth.rs  — «маскировка»: аргументы Chrome, CDP-инъекция скрипта,
               человеческие паузы/клики/ввод
  resume.rs   — ResumeBuilder: открытие редактора резюме hh.ru и заполнение полей
  scraper.rs  — VacancyScanner: построение URL поиска, парсинг выдачи, ранжирование,
               apply_to_vacancy (отклик на одну вакансию)
  mdresume.rs — парсер Markdown-резюме → ResumeData (+ unit-тесты)
  types.rs    — общие типы: Config, Credentials, ResumeData
```

### Пайплайн операций (app.rs)

```
Session::start(config)         → запуск Chrome с профилем, CDP-маскировка
  └─ Session::login(config, creds)
        ├─ если session.json есть → восстановить cookie → проверить вход
        └─ иначе                  → полный логин (формы + кнопка), сохранить cookie
VacancyScanner.search(resume)   → GET /search/vacancy?text=<keywords>[&area=<…>]
  └─ парсинг карточек → Vacancy[]
rank_vacancies(&mut list)       → сортировка по убыванию score
apply_to_vacancy(driver, …)     → открыть вакансию → клик «Откликнуться» →
                                  подтвердить, если появилась модалка
```

### Ранг релевантности (score)

Для каждого ключевого слова (регистронезависимо):
- встречается в **заголовке** вакансии → +3;
- встречается в **сниппете описания** → +1.

Сумма по всем ключевым словам и есть `score`. Вакансии с `score == 0` к отклику
не допускаются.

## 7. Имитация человека и защита от детекции (`stealth.rs`)

Приложение специально сделано так, чтобы не выдавать себя за бота:

**При запуске Chrome:**
- используется **постоянный профиль** (`profile_dir`): начиная со второго
  запуска у браузера «человеческая» история, cookie, сессии;
- исключается переключатель `enable-automation` и баннер «управляется
  автоматизированным ПО»;
- флаг `--disable-blink-features=AutomationControlled` — прячет признак
  `<blink features>AutomationControlled`;
- `--disable-infobars`, `--no-first-run`, `--no-default-browser-check`,
  `--disable-popup-blocking`, `--lang=ru-RU`;
- через CDP (`Page.addScriptToEvaluateOnNewDocument`) в каждую новую страницу
  инжектится скрипт, который:
  - прячет `navigator.webdriver` (геттер возвращает `undefined`);
  - подставляет «плагины» как у настоящего Chrome;
  - подменяет `navigator.languages` на `['ru-RU', 'ru', 'en-US', 'en']`;
  - сохраняет реальный результат `permissions.query` для notifications.

**Во время действий:**
- `pause()` — случайные паузы в заданном диапазоне миллисекунд (между действиями);
- `type_like_human()` — ввод текста **по одному символу** с переменной скоростью
  и чуть более длинными паузами между словами;
- `human_click()` — движение мыши к центру элемента и клик через цепочку действий
  с задержками;
- `human_fill()` — фокус → клик → очистка поля → «человеческий» ввод;
- `find_and_click()` — поиск первого доступного селектора со случайными паузами
  между попытками.

**Устойчивость к падениям профиля.** Если Chrome остался от предыдущего запуска
(аварийно завершился), в каталоге профиля висят файлы `SingletonLock`
/ `SingletonSocket`/`SingletonCookie`, и новый Chrome отказывается стартовать.
Перед запуском бот безопасно их удаляет (`clean_stale_profile_lock`).

**Совместимость с chromedriver.** Используются `ChromeCapabilities` с
`browserName: "chrome"` (не `"chromium"`) — иначе современный chromedriver
отвечает «No matching capabilities found».

## 8. Сессия и вход (варианты)

1. **Возобновление.** При наличии `session.json` бот кладёт сохранённые cookie в
   браузер, обновляет страницу и проверяет признак входа —
   ссылку профиля `a[data-qa="mainmenu_applicantProfile"]`. Успех — разблокировка
   мгновенная, без нового логина.
2. **Полный логин.** Если сессии нет/протухла: открывается
   `https://hh.ru/account/login`, `human_fill` подставляет `login` и `password`,
   кнопка входа ищется по селекторам (`button[data-qa="account-signup-submit"]`
   или `button[type="submit"]`) и нажимается через `find_and_click`. Затем бот до
   300 секунд опрашивает статус входа.
3. **Ручная проверка / капча.** Пока бот ждёт, тот же открытый браузер — ваше
   окно: можно вписать реальные данные, решить капчу, пройти 2FA. Как только
   вход засчитан, cookie сохраняются в `session.json`.

> Вы всегда можете проверить состояние: `hh_bot login` в консоли или кнопка
> «Войти на hh.ru» в панели.

## 9. Селекторы hh.ru (текущие, могут меняться)

| Что | Селектор |
|-----|----------|
| Список вакансий в выдаче | `div[data-qa="vacancy-serp__vacancy"]` (+ вариант с `_highlighted`) |
| Заголовок/ссылка вакансии | `a[data-qa="serp-item__title"]` |
| Компания | `a[data-qa="vacancy-serp__vacancy-employer"]` |
| Зарплата | `span[data-qa="vacancy-serp__vacancy-compensation"]` |
| Сниппет обязанностей | `div[data-qa="vacancy-serp__vacancy_snippet_responsibility"]` |
| Кнопка отклика | `a[data-qa="vacancy-response-link-top"]` / `...-bottom` |
| Подтверждение (модалка) | `button[data-qa="vacancy-response-submit"]` |
| Признак входа | `a[data-qa="mainmenu_applicantProfile"]` |
| Логин/пароль | `input[name="login"]`, `input[name="password"]` |
| Кнопка входа | `button[data-qa="account-signup-submit"]` / `button[type="submit"]` |

Селекторы централизованы в модулях (`resume.rs`, `scraper.rs`, `session.rs`) —
при изменении разметки hh.ru править нужно в одном месте.

## 10. Ограничения и поведение в нестандартных случаях

- **Не найдены вакансии/изменился селектор** → идёт ошибка с понятным
  сообщением, бот не падает молча.
- **Нет кнопки отклика** → отклик помечается как `failed`, обработка
  продолжается (пауза 3 с между вакансиями).
- **Модалка не появляется** → отклик считается отправленным напрямую (в
  современном hh.ru чаще всего так и есть), ожидание `max_wait = 60 c`.
- **`resume.json` без ключевых слов** → запуск остановлен с сообщением.
- **Отсутствует `credentials.json`** → понятная ошибка при первой необходимости.
- **Капча** → вход ждёт ручного прохождения в браузере (до 300 с; таймаут
  константа в `wait_for_login`, легко изменить).
- **Лимит откликов** настраивается в `config.json` (`max_applies_per_run`),
  чтобы не «спалить» аккаунт массовыми действиями.

## 11. Стек и библиотеки

- **thirtyfour 0.35** — Selenium WebDriver (W3C) для Rust: управление Chrome,
  CDP-вызовы (`ChromeDevTools`), цепочки действий (`action_chain_with_delay`).
- **axum 0.8 / tokio** — асинхронный HTTP-сервер панели (resp. runtime).
- **serde / serde_json** — типы и обмен JSON (включая cookie `session.json`).
- **anyhow** — удобная обработка ошибок; **tracing** — журналирование.
- **dirs** — кроссплатформенный путь к конфигу; **rand** — «человеческий»
  разброс задержек; **async-trait** — служебно.

## 12. Архитектурная заметка по `session.json`

Структура — `{"cookies": [...]}`. Сохраняются только cookie с доменом, содержащим
`hh.ru` (фильтр `cookie_json_is_session`). Восстановление — сериализация каждого
cookie обратно в `thirtyfour::Cookie` и `add_cookie` подряд от старого к новому.
